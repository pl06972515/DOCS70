>[!WARNING|style: flat|label: 简要说明 ]
>
><span style='color:red'>[ 整洁架构`Clean Architecture`- 基于`DDD`]</span>
>
><span style='color:red'>[ 其核心思想是 - 依赖原则：依赖只能从外层指向内层，内层对外层一无所知 - 这样可以提升系统的可维护性、可测试性和可扩展性 ]</span>
>
>- <span style='color:Blue'>[`A`] 分层架构：代码按职责分为多层，如接口层、应用层、领域层、基础设施层 </span><span style='color:red'>[ 确保各层职责明确 - 互补干扰 ]</span>
>- <span style='color:red'>[`B`] 依赖规则：外层依赖内层，内层不感知外层</span>
>
>- <span style='color:Blue'>[`C`] 领域模型：包含业务实体、业务规则和领域服务</span><span style='color:red'>[ 与技术无关 ]</span>
>
>![3-代码分层](wwwroot\DocImages\c2_1.0.0.png ':size=700')
>
>![c2.0.0](wwwroot\DocImages\c2.0.0.png ':size=700')
>
><span style='color:red'>[ ☢ 不同于传统的三层架构不一样 ]</span>
>
>- <span style='color:red'>[ 领域层`Domain`] 包含领域对象、实体、值对象、聚合根、领域服务等 [ 专注于表达业务概念 + 业务规则 ]</span>
>
>- <span style='color:red'>[ 应用层`Application`] 负责编排业务流程、用例、命令和查询 [ 但不包含复杂的业务规则 - 只做流程协调 ]</span>
>
>  <span style='color:red'>[ 流程协调：应用层负责协调各个领域服务、实体、仓储等对象的调用顺序，实现业务的完整流程 - 但不实现具体的业务规则或复杂逻辑 ]</span>
>
