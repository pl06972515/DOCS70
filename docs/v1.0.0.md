>[!WARNING|style: flat|label: 微服务服务拆分原则 ]
>
><span style='color:Blue'>[`A`] 纵向( 垂直 )拆分 ( 按业务维度 )</span>
>
>- <span style='color:red'>核心思想：</span>以业务为中心，将不同的业务功能模块 [ 拆分为独立的服务 ]
>
>- <span style='color:red'>最终目标：</span>每个服务聚焦于单一业务能力<span style='color:red'> [ 实现高内聚、低耦合 ]</span>
>
>   <span style='color:red'>注意事项：</span>
>
>   <span style='color:red'>[ 避免服务膨胀：不要将过多、无关或强依赖的业务功能聚合到同一个服务中 ]</span>
>
>   <span style='color:red'>[ 相关或强依赖的业务应聚合在同一服务，减少跨服务调用和复杂度 ]</span>
>
>
><br/>
>
><span style='color:Blue'>[`B`] 横向拆分 ( 按通用能力 )</span>
>
>- <span style='color:red'>核心思想：</span>将跨业务、通用的功能（如认证、鉴权、日志、网关、消息、监控等）抽取出来 <span style='color:Blue'>[ 形成独立的基础服务或中台服务 ]</span>
>
>- <span style='color:red'>最终目标：</span>为各业务服务提供统一、可复用的能力，提升开发效率和系统一致性
>
>   <span style='color:red'>注意事项：</span>
>
>   <span style='color:red'>[ 避免重复开发：通用能力只需实现一次，供所有业务服务复用 ]</span>
>
>   <span style='color:red'>[ 基础服务应保持通用性和独立性，避免与具体业务强耦合 ]</span>
>
>
><br/>
>
><span style='color:red'>[`C`] 服务拆分的关键点</span>
>
>- <span style='color:red'>[ 避免服务膨胀 ] 无论纵向还是横向拆分，都要防止单个服务变得过于庞大 [ 导致维护困难、部署复杂和扩展受限 ]</span>
>- <span style='color:red'>[ 高内聚、低耦合 ] 服务内部功能紧密相关，服务之间依赖尽量减少，接口清晰</span>
>- <span style='color:red'>[ 服务自治 ] 每个服务应能独立开发、部署和扩展，减少对其他服务的影响</span>
>
>
